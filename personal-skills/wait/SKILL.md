# 잠깐, 다시 설명

이해가 끊긴 설명과 연결된 의사결정·구현을 멈춥니다. 요청한 목표와 현재 진행 위치는 유지합니다.

위임한 작업이나 실행 중인 명령이 있으면 [병렬 지침의 중단과 재개](../_shared/parallel-delivery.md#중단과-재개)를 적용합니다. 설명하는 동안 해당 작업자가 계속 수정하게 두지 않습니다. 전체 중단 요청은 모든 활성 작업에 전달하고, 중단 확인 전에는 완료됐다고 말하지 않습니다. 단일 작업이고 실행 중인 명령도 없으면 별도 제어 절차를 만들지 않습니다.

지금 풀려는 문제, 빠진 배경, 제안의 뜻, 작은 실제 예시, 현재 선택을 필요한 만큼 연결해 쉬운 한국어로 다시 설명합니다. 짧게 만들려고 전제를 더 생략하지 않습니다. 필요한 용어는 처음에 풀고 프로젝트의 합의된 말을 씁니다. 개념을 이해하지 못하는 사람에게 먼저 기술 선택을 떠넘기지 않습니다.

제안 자체가 이 작업에 불필요했다면 이유를 설명하고 줄입니다. 이해를 돕는 설명을 새 강의·시험·문서 생성으로 확대하지 않습니다. 이해했다는 가정으로 방금 멈춘 작업을 자동 재개하지 않습니다. 사용자가 계속하라고 하거나 설명과 계속 진행을 함께 요청했다면 기존 승인 범위와 진행 위치에서 이어갑니다. 별도 승인 양식은 필요하지 않습니다.

예: “통합 브랜치가 왜 필요해?”에는 여러 사람이 만든 변경을 모아 함께 동작하는지 확인하는 작업본이라고 설명하고, 현재 작업에 병렬 구현이 실제로 필요한지도 연결합니다. 원래 요청이 문구 하나 변경이라면 그 절차가 필요하지 않다고 바로잡습니다.
