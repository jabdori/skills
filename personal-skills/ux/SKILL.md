# 사용자 관점의 화면과 흐름

[공통 작업·문서 지침](../_shared/personal-workflow.md)을 읽고 필요한 부분을 적용합니다.

## 행동

1. 사용자가 하려는 일과 막히는 지점을 실제 화면·요청·사용 흐름에서 확인합니다. 스크린샷만 볼 수 있다면 외관에 관한 관찰과 미확인 상호작용을 구분합니다.
2. 첫 화면에서 알아야 할 내용과 행동을 정합니다. 중요하지 않은 상태·구현 메타데이터를 걷어내고 질문에 맞는 표현을 선택합니다. 항상 카드·칸반·다이어그램을 추가하지 않습니다.
3. 검토만 요청했으면 근거 있는 제안으로 끝냅니다. 수정이 허용됐다면 대상 화면·흐름에 필요한 변경을 하고 기존 디자인 관례를 따릅니다.
4. 변경한 범위의 실제 화면과 관련 상호작용을 가능한 도구로 확인합니다. 자동 테스트만으로 시각적 이해가 개선됐다고 단정하지 않습니다. 관측하지 못한 부분을 명시합니다.
5. 제품 흐름이나 중요한 결정이 바뀌면 현재 문서의 해당 설명·그림을 갱신합니다. 국소적인 간격·문구 조정에는 새 현황 문서를 만들지 않습니다.

자신이 만든 화면을 직접 확인해야 할 때는 [원문·화면 확인 도구](../_shared/agent-browser.md)의 화면 조작·증거 기록 범위만 적용합니다.

## 종료와 예시

대상 사용 흐름의 문제가 개선됐는지 설명할 근거가 있으면 끝냅니다. 요청 밖의 디자인 시스템·설정 화면·관리 앱을 만들지 않습니다.

“한눈에 현황이 안 보여”라면 먼저 필요한 질문과 정보량을 확인합니다. 순서가 문제면 작은 시퀀스, 조건이 문제면 분기, 여러 작업 비교면 정적 표를 택합니다. 복잡한 대시보드를 접어 두는 것으로 근본적인 사용 부담 해소를 대신하지 않습니다.
