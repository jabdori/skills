# 코드와 설명 지도

새 문서는 `docs/explain/code-map.md`에 두고 제출 전에 실제 코드·검사와 대조해 채웁니다. 사용자가 AI 없이 몇 분 안에 읽고 설명할 수 있게 씁니다.

## 해결 흐름

실제 결과 한 줄에서 출발해 값을 만든 함수 → 읽은 데이터 → 결정한 줄 → 이유를 거꾸로 따라갑니다. `docs/task/data-map.md`의 한 건과 같은 레코드를 우선 쓰고, 코드에 없는 문장은 `계획만 있음/구현 안 됨`으로 표시합니다.

| 결과의 실제 한 줄 | 값을 만든 함수 | 읽은 데이터 | 결정한 근거(파일:줄) | 왜 이 결과인가 | 대조한 커밋 SHA |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

### 알고리즘 순서 카드

대조한 커밋 SHA: [SHA]. 문제를 푸는 실제 단계만 적고 파일:줄은 근거로만 둡니다.

| 순서 | 들어온 것 → 한 일 → 나온 것 | 적용한 업무 규칙(쉬운 말) | 왜 이 단계가 먼저인가 | 근거(파일:줄 또는 구현 안 됨) |
|---|---|---|---|---|
| ① |  |  |  |  |
| ② |  |  |  |  |
| ③ |  |  |  |  |
| ④ |  |  |  |  |
| ⑤ |  |  |  |  |

왜 이 순서인가: [한 줄]. 같은 실제 레코드의 작은 숫자 예시: [입력 → 단계별 값 → 결과]. 순서를 바꾸면: [실제로 바꿔 확인한 결과 또는 미확인].

### 문제 해결의 조건 처리표

대조한 커밋 SHA: [SHA]. 함수 안의 분기가 아니라 문제의 업무 조건과 판단 기준을 적습니다.

| 순서 | 문제의 조건(쉬운 말) | 종류(꼭 지킬 규칙/대립하는 판단 기준) | 어떻게 처리했나 | 왜 이 순서인가 | 근거(담당자 답·검사·파일:줄 또는 구현 안 됨) |
|---|---|---|---|---|---|
| ① |  |  |  |  |  |

조건이 부딪히면 무엇을 우선했나: [한 줄]. 순서를 바꾸면 무엇이 달라지나: [실제 숫자 또는 미확인].

## 코드 전체 지도

| 책임 폴더 | 맡은 일(한 줄) | 핵심 파일:줄·함수 | 이 폴더의 제출 파일 | 연결되는 파일·입출력 |
|---|---|---|---|---|
| [진입점/모델/자료/계산/검사/저장/화면·API/설정 중 실제 있는 것] |  |  |  |  |
