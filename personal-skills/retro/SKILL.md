# 경험을 다음 작업에 반영

[공통 지침](../_shared/personal-workflow.md)을 적용합니다. 실제 기록과 파일을 근거로 개선하며 모델의 의도나 근거 없는 원인을 단정하지 않습니다.

## 행동

1. 지정한 작업의 요청·실제 변경·명령 결과·실패·수정 기록을 읽습니다. 기록이 부족하면 확인할 수 있는 범위와 원인 가설을 구분합니다. 사용자가 허용하지 않은 다른 프로젝트의 자료까지 찾지 않습니다.
2. 반복 탐색, 잘못 이해한 용어, 검사를 실행하지 않은 완료 주장, 불필요한 절차·도구·문서 같은 실제 비용을 찾습니다. 이미 있는 검사가 실행되지 않았는지부터 확인하고 비슷한 검사나 새 체계를 중복 생성하지 않습니다.
3. 관측 → 원인 근거 → 가장 작은 개선 → 적용 위치 → 확인 방법을 정합니다. 제품 버그는 해당 코드·회귀 검사, 프로젝트 특성은 프로젝트 지침·기존 문서, 여러 작업에서 재현된 행동 문제는 해당 개인 스킬을 후보로 삼습니다. 효과 없는 규칙은 추가보다 삭제·정리를 고려합니다.
4. 제안만 요청받았다면 근거와 개선안을 답합니다. 반영까지 요청받았다면 승인된 범위의 파일을 직접 고칩니다. 프로젝트 회고를 전역 지침·개인 스킬·장기 메모리 변경 권한으로 확대하지 않습니다. 별도 회고 파일은 기본으로 만들지 않습니다.
5. 가능한 작은 사례에서 개선 전후의 실제 행동을 확인합니다. 검사 명령 수정은 실제로 검사가 수집·실행되고 기존 실패를 잡는지 봅니다. 실패가 드러난 것은 탐지 개선일 수 있으며 제품 수정 성공과 구분합니다.
6. 변경된 규칙이 영향을 줄 기존 정상 사례도 함께 확인합니다. 예를 들어 검사 누락을 고쳤다면 인계만 하는 요청까지 전체 검사를 요구하게 되지 않았는지 봅니다. 기존 예제·검사를 재사용하고, 행동 검증에 작업자가 필요하며 위임이 허용되면 새 문맥에 짧은 요청과 필요한 프로젝트만 줍니다. 정답·수정 이유·원하는 호출 순서를 요청에 넣지 않습니다. 실패 사례만 좋아지고 정상 사례가 나빠졌다면 규칙을 좁히거나 해당 변경을 재검토합니다. 검증을 약하게 바꿔 통과시키지 않습니다.

다음 작업자·새 문맥·정상 대조 사례 중 확인하지 못한 범위는 명시합니다. 관찰한 사례에 필요한 가장 작은 변경만 채택하며, 효과가 불분명하면 개선 가설로 남깁니다. 자동 재귀 수정·전체 스킬 재시험을 매 작업에 붙이지 않습니다. 모델이나 지침이 바뀌어 기존 보조 절차가 불필요해졌다면 관련 사례로 확인한 뒤 줄입니다.

## 결과 형식과 종료

필요한 항목만 `관측·근거 | 개선과 적용 위치 | 실행한 확인 | 재사용 조건·한계`로 답합니다. 재사용할 규칙은 이미 있는 적절한 문서에 남기고 시행착오 전체를 현재 문서에 누적하지 않습니다. `AGENTS.md`에는 다음 작업의 행동·명령과 필요한 이유만 두며, 일회성 실행 내역과 남은 제품 버그는 응답 또는 기존 현재 문서에서 설명합니다. 개선을 적용·확인했거나 정확한 미확인 경계가 드러나면 끝냅니다. 모든 회고를 CI 구축이나 지침 자동 개정으로 확대하지 않습니다.
