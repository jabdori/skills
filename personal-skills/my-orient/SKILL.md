# 현황 파악과 재개

[공통 작업·문서 지침](../_shared/personal-workflow.md)을 읽고 필요한 부분을 적용합니다.

## 행동

1. 기존 현재 문서에서 목적·지금 상태·남은 일·다음 행동을 읽습니다. 제품 완성을 맡았다면 연결된 기존 요구·완료 조건까지 확인해 현재 작업이 전체 목표의 어디에 해당하는지 판단합니다. 실제 작업 경로와 관련 파일, Git을 사용하는 경우 현재 브랜치·변경을 대조합니다.
   평가·과제 환경이면 안내문과 README에서 제공된 담당자와 담당 범위, 허용 도구·모델, 남은 시간, 필수 제출물과 형식, AI가 담당자 채팅에 직접 접근할 수 있는지를 먼저 확인합니다. 확인되지 않은 규칙은 미확인으로 두고 다른 행사의 규칙으로 채우지 않습니다. 시간과 제출 조건에 필요한 절차만 적용하며 PR·`AGENTS.md` 정비·후크·병렬 구현을 기본으로 붙이지 않습니다.
2. 이어갈 사용자 흐름에 필요한 코드·설정·기존 검사만 확인합니다. 문서의 구현 주장과 실행 확인 여부를 구분합니다.
3. 불일치가 있으면 실제 파일과 근거로 현재 상태를 판단합니다. 수정 권한이 있으면 같은 문서의 해당 부분을 고치고, 읽기 전용이면 응답으로 차이만 알립니다.
4. 다음 수정 위치와 확인 방법을 구체적으로 정합니다. 계속 진행하라는 요청이면 승인된 다음 작업을 수행하며 현황 보고만 하고 멈추지 않습니다.

업무 의미가 모호하면 현재 문서의 용어 표나 기존 영역별 용어 지도에서 관련 부분만 읽습니다. 프로젝트 작업 기준 정착·`AGENTS.md` 정비까지 요청받았을 때는 `my-init`의 역할이며, 일상 재개마다 초기화를 반복하지 않습니다. 결과는 현재 사실·문서와의 차이·다음 위치·확인 방법으로 전달합니다.

## 종료와 예시

현재 상태, 이어갈 위치, 확인 방법을 알 수 있으면 현황 조사를 끝냅니다. 조사만 요청했다면 보고로 끝내고, 이어서 완성하라는 요청이면 다음 승인 작업의 구현·검증을 시작합니다. 첫 검증이 통과했어도 기존 요구가 남아 있으면 다음 작업으로 이어갑니다. 인벤토리·전체 의존성 그래프·새 관리 도구를 만들지 않습니다.

“이 문서 보고 검색 작업 이어가줘”라면 현재 문서와 검색 경로를 대조하고 다음 승인 작업을 이어갑니다. 과거 검증 이후 관련 코드가 바뀌었으면 재확인 필요를 표시합니다. 모든 테스트가 이미 통과했고 변경도 없다면 동일 검사를 관행적으로 반복하지 않습니다.
