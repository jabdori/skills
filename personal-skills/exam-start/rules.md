# 작업 규칙
- 업무 방식·예외·성공 기준은 추측하지 말고 담당자 질문안을 응답 끝에 적는다. 내가 답 원문을 붙여넣으면 brief 호출 없이 근거표에 반영하고, 화자가 불명확하면 한 줄로 먼저 묻고, 이미 받은 답·남은 질문만 짧게 보여준다.
- 답이 모이면 문제·성공 기준·만들 것과 안 만들 것·제약을 담당자 확인용 요약으로 만든다. 수정 전에는 원인과 계획을 먼저 보여준다.
- 코드·데이터로 확인되는 사실은 직접 확인한다. 우선순위·범위는 근거와 추천을 주고 내가 정한다.
- 요구마다 근거를 구분해 docs/requirements/evidence.md 표에 기록·갱신한다: 담당자 답변 / 제공 자료 / 코드·실행 결과 / 내 결정 / 미확인 가정.
- 작은 단위로 구현하고 실행해서 확인한다. 동작 여부와 업무 요구 충족을 따로 보고한다.
- 요청 밖 기능·도구·문서·병렬 작업을 늘리지 않고, 요청과 무관한 코드·형식은 바꾸지 않으며, 같은 검사를 반복하지 않는다.
- 상황별 스킬을 쓴다: 담당자 답 정리·합의는 brief, 구현 순서·결정은 plan, 구현은 build, 제출 전에는 verify·explain·learn, 원인 모를 실패는 debug. 스킬이 없으면 이 규칙대로 직접 한다.
- Git push·외부 전송·개인 파일 업로드, Codex 업데이트·설정 변경은 하지 않는다. 시작 상태와 합의·주요 결정·검증된 단위마다 한국어 Conventional Commits 메시지로 로컬 커밋한다.
- 모델은 권장 모델(Sol 6.1·Terra 5.6·Luna 6·Sol 6.0)만 쓰고 Astra는 쓰지 않는다. 하위 에이전트도 같다.
- 웹 서버는 0.0.0.0에 바인딩하고 실제 포트를 알려준다.
- README·과제 안내의 필수 제출물과 파일명을 따른다. HOW_TO_RUN.md·AI_COLLABORATION.md처럼 내가 쓰는 제출 문서는 내가 명시적으로 요청할 때만 만들거나 고치고, 평소에는 확인된 재료만 docs/에 준다. 결정 문서에는 판단·근거·검증·한계를 쓴다.
- 응답·문서·커밋 메시지·코드 주석은 모두 한국어로 쓴다(코드 식별자·명령·파일 이름은 원문). 결과는 내가 코드 위치와 함께 직접 설명할 수 있게 초보자도 알 쉬운 말로 설명한다. 문서 그림은 docs/assets/의 별도 SVG를 상대 경로로 연결하고, 터미널에서는 ASCII로 그린다(Mermaid·인라인 SVG 금지).
