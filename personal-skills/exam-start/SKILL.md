# 응시 시작 준비

작업 폴더에서 한 번 수행합니다. 제품 코드는 수정하지 않습니다.

`AGENTS.md`를 고치기 전에 이 `SKILL.md`가 있는 폴더 기준의 [로컬 커밋 규칙](../_shared/personal-workflow.md#로컬-커밋)으로 시작 상태를 기록합니다: Git이 없으면 `git init`하고, `HEAD` 커밋이 없거나 기존 커밋 뒤 미커밋 변경이 있으면 `chore: 과제 시작 상태`와 한국어 본문으로 커밋하며, 변경 없는 기존 HEAD는 시작 기준으로 삼습니다. 커밋 전에는 저장소 루트에 실제로 있고 과제가 제공하지 않은 홈 설정 점 폴더(`.agents/`, `.codex/`, `.config/`, `.cache/` 등)만 그 저장소의 `.git/info/exclude`에 루트 고정 패턴으로 추가합니다.

1. 기존 `AGENTS.md`를 먼저 읽고 시스템 환경 정보와 사용자 추가 규칙을 짧게 알려 줍니다. 없으면 새 파일을 만듭니다. 기존 내용은 지우거나 일반 양식으로 교체하지 않습니다.
2. [작업 규칙 원본](rules.md)의 각 줄을 기존 지침과 의미로 대조해 겹치거나 충돌하는 줄은 건너뛰고, 나머지만 `AGENTS.md` 맨 아래에 덧붙입니다. 제목도 중복시키지 않으며 이미 덧붙인 규칙은 다시 넣지 않습니다. 충돌은 조용히 덮지 말고 알립니다.
3. `AGENTS.md`를 읽거나 만든 뒤 커밋 여부와 관계없이 시작 커밋의 SHA, 필수 산출물·지정 양식·수정 금지 파일을 `## 이 프로젝트`에 적되 수정 금지 목록은 `- 수정 금지 파일: README.md, <파일>` 형식으로 씁니다. 현재 읽는 이 `SKILL.md`가 있는 폴더의 상위에 `_shared`가 실제로 있는지 확인해 `스킬 공용 자료: <절대 경로>`(예: `/home/user/.agents/skills/_shared`)도 적고, 찾지 못하면 임의 경로를 쓰지 않으며 [init](../init/SKILL.md)의 방식으로 실행·테스트 명령과 포트는 확인된 것만 적고 못 찾은 항목은 `못 찾음`으로 적습니다.
4. [orient](../orient/SKILL.md)의 범위로 [과제 지시문 정리표](../_shared/personal-workflow.md#과제-지시문-정리표)를 첫 결과로 한 화면에 보여 주고, 본인 경험·의견을 묻는 직접 작성 문서를 표시하며 제공 데이터의 차이·이상값·해석이 필요한 조건을 훑어 영향 큰 담당자 질문 상위 5~7개만 먼저 제시하고 나머지는 보류 목록에 둡니다. 제공 자료에 업무 요구가 있으면 [brief](../brief/SKILL.md)에 따라 정리표 행을 근거표에 넣으며 담당자 답이나 업무 사실을 지어내지 않습니다.
5. 정리표 다음의 마지막 주요 결과인 `시작 경로`에는 데이터 지도(파일별 행 수·열·예시 3행·파일 간 관계·이상값과 담당자 질문), 문제 유형 이름을 붙인 단계별 `입력 → 처리 → 출력` 한 줄, 규칙 검사기, 첫 1시간에 가장 단순한 방법으로 끝까지 통과시킬 걷는 뼈대, 이후 요구의 우선순위와 시간 배분을 담고 지시문에 제한 시간이 없으면 180분을 기본으로 배분합니다. 전체를 이해할 때까지 기다리지 말고 뼈대부터 통하게 한다는 원칙을 한 줄로 알립니다.

`AGENTS.md`와 정리표를 지정 제출 문서에 반영한 뒤 [로컬 커밋 규칙](../_shared/personal-workflow.md#로컬-커밋)으로 `docs: 작업 규칙과 과제 정리표`와 한국어 본문을 사용해 로컬 커밋합니다.

시작 경로 끝에 한 줄로 알립니다: **AGENTS.md를 직접 읽고, DMs의 담당자 수를 확인한 뒤, 질문은 본인이 직접 보내 주세요.**
