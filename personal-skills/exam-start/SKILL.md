# 응시 시작 준비

작업 폴더에서 한 번 수행합니다. 제품 코드는 수정하지 않습니다.

1. 기존 `AGENTS.md`를 먼저 읽고 시스템 환경 정보와 사용자 추가 규칙을 짧게 알려 줍니다. 없으면 새 파일을 만듭니다. 기존 내용은 지우거나 일반 양식으로 교체하지 않습니다.
2. [작업 규칙 원본](rules.md)의 각 줄을 기존 지침과 의미로 대조해 겹치거나 충돌하는 줄은 건너뛰고, 나머지만 `AGENTS.md` 맨 아래에 덧붙입니다. 제목도 중복시키지 않으며 이미 덧붙인 규칙은 다시 넣지 않습니다. 충돌은 조용히 덮지 말고 알립니다.
3. [init](../init/SKILL.md)의 확인 방식으로 실제 실행·테스트 명령, 포트, 제출 파일명을 확인해 `## 이 프로젝트` 구역을 짧게 쓰거나 갱신합니다. 확인되지 않은 명령과 진행 상황·기능 목록은 넣지 않습니다.
4. [orient](../orient/SKILL.md)의 범위로 현재 동작과 과제 요구의 차이를 정리하고, 확인 가능한 담당자별 질문안을 줍니다. 제공 자료에 업무 요구가 있으면 [brief](../brief/SKILL.md)에 따라 근거표를 시작합니다. 담당자 답이나 업무 사실을 지어내지 않습니다.

마지막에 한 줄로 알립니다: **AGENTS.md를 직접 읽고, DMs의 담당자 수를 확인한 뒤, 질문은 본인이 직접 보내 주세요.**
