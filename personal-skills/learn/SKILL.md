# 내 작업 이해하기

목표는 제출 전 10분 동안 보지 않고 떠올려 실제 동작을 설명하는 것입니다. [explain의 결정 설명](../explain/SKILL.md#설명과-인계)과 [설명 카드](../_shared/templates/설명카드.md)의 근거 연결을 재사용하되, 학습 문서나 정답을 먼저 보여 주지 않습니다. AI 사용이 금지된 서술형이 시작되기 전 작업 시간에만 연습합니다.

1. 실제 코드·검사·결정 문서·담당자 대화와 접근 가능한 세션 기록을 읽고 사용자 동작 하나를 입력부터 출력·외부 연동까지 추적합니다. 바뀐 동작, 요구와 구현 위치, 실패·경계, 검사의 보장 범위, AI가 한 일과 사용자가 직접 확인한 일을 설명할 수 있게 실제 코드에 맞는 질문 6~8개를 준비합니다. “이 요구가 바뀌면 어디를 고치나”, “이 증상이면 어디부터 보나”, “이 입력이면 무엇이 나오나”처럼 적용형을 절반 이상으로 하고 보기나 정답 단서는 주지 않습니다. 질문에는 공개된 Cofa 예시 유형인 “AI에 맡긴 일과 내가 직접 판단·확인한 일(기록으로 확인되는 것과 안 되는 것)”과 내가 쓴 지침·문서(`AGENTS.md`·결정 문서·근거표)가 실제 코드·검사와 일치하는지를 묻는 문항을 각각 포함하되, 담당자에게 무엇을 물어 알아냈는지는 접근 가능한 세션 기록으로 확인될 때만 묻습니다.
2. 질문을 하나씩 내고 사용자가 자료를 보지 않고 답하면 곧바로 실제 코드·실행 결과와 대조해 **맞은 점·빠진 점·근거(파일:줄)**를 알려 줍니다. 필요한 경계·실패 사례는 안전한 범위에서 직접 실행하며, 기록된 실행과 이번 실행, 확인하지 못한 사실을 구분합니다. 사용자가 직접 검증했다는 기록이 없으면 대신 주장하지 않습니다.
3. 틀리거나 빠진 개념만 [설명 카드](../_shared/templates/설명카드.md) 또는 과제 지정 제출 문서의 `학습` 구역에 짧게 남기고 제출 직전에 그것만 다시 보게 합니다. 답할 시간이 없으면 질문을 먼저 남기고 정답 기준은 아래의 접힌 구역에 가립니다.

시험·과제 작업 폴더에서는 별도 파일을 늘리지 않고 `설명카드.md` 또는 과제가 지정한 제출 문서에 합칩니다. 평소 프로젝트에서는 `docs/` 등 기존 문서 위치를 씁니다. 확인한 범위보다 크게 가르치지 않습니다.
