# 조사와 판단 근거

[공통 작업·문서 지침](../_shared/personal-workflow.md)을 읽고 필요한 부분을 적용합니다.

## 행동

1. 요청한 질문, 대상과 시점, 조사 범위를 파악합니다. 확인 가능한 식별 정보는 직접 찾고 결과를 바꾸는 모호함만 질문합니다.
2. 공식 안내·원문·실제 소스를 우선 확인합니다. 현재성이 필요한 사실은 현재 자료로 검증합니다. 후기와 2차 설명은 경험의 근거로 사용하고 공식 요건으로 바꾸지 않습니다.
3. 확인된 사실, 근거에서 도출한 추론, 확인되지 않은 것을 구별합니다. 주장 가까이에 원문 링크와 필요한 기준 날짜를 남깁니다. 공개 자료가 없으면 그 한계를 적습니다.
4. 조사 결과가 현재 선택과 다음 행동을 어떻게 바꾸는지 설명합니다. 비교가 필요하면 선택에 영향을 주는 차이를 표로 정리합니다.
5. 문서 갱신이 요청 범위에 포함되면 현재 문서의 결론·근거·남은 질문만 반영합니다. 조사만 요청했다면 구현·설치·가입으로 이어가지 않습니다.

## 조사 깊이

- 시작할 때 고른 깊이와 이유를 한 줄로 알리고 승인받지는 않습니다. 사용자가 조사 깊이를 명시했다면 그 지시를 우선합니다.
- 버전·옵션·API 형식·날짜처럼 답이 사실 하나이고 공식 원문 하나로 확정할 수 있으면 빠르게 확인합니다. 빠른 확인 중 출처가 엇갈리거나 공식 근거가 없거나 답이 선택·판단을 바꾸면 심층으로 올립니다.
- 무엇을 쓸지·어떻게 할지·해도 되는지처럼 결정이 달라지거나 하위 질문이 여럿이거나 낯선 분야, 엇갈린 출처, 판단에 필요한 최신성·경험 근거가 있으면 심층으로 조사합니다. 하위 질문 3~5개와 각 질문의 공식·원문 출처 계획을 세우고 검색어를 바꿔 여러 번 찾은 뒤 원문을 직접 읽으며, 엇갈린 주장은 날짜·출처 등급으로 대조하고 빈 곳만 한 번 더 찾습니다.
- 심층 모드에서만 이 `SKILL.md`가 있는 폴더 기준의 [조사 근거표](../_shared/templates/조사근거.md)를 씁니다. 자료를 못 찾으면 `| 하위 질문 | 주장 | 출처(URL·날짜·등급) | 인용 | 판정 | 남은 의문 |` 머리줄로 시작합니다. 각 하위 질문은 엇갈림이 없고 공식 출처 1개 또는 독립 출처 2개가 있으면 `확인됨`, 주장이 충돌하면 `엇갈림`, 근거가 모자라면 `미확인`으로 판정한 뒤 끝내며 무기한 탐색하지 않습니다. 독립 하위 질문이 많을 때만 [병렬 지침](../_shared/parallel-delivery.md)에 따라 위임합니다.

원문 본문을 읽을 때는 [원문·화면 확인 도구](../_shared/agent-browser.md)를 필요할 때만 참고합니다.

## 종료와 예시

요청한 범위의 질문에 근거와 한계를 붙여 답하고 준비 판단을 할 수 있으면 끝냅니다. 관련 자료가 더 있다는 이유만으로 무기한 탐색하지 않습니다.

“SK 해커톤에서 쓰는 Cofa를 조사해줘”라면 행사 규칙과 플랫폼 사용 경험을 구분합니다. 다른 행사의 후기는 기능 사용에 참고하되 해당 SK 행사의 채점 기준으로 단정하지 않습니다. 공식 배점이 확인되지 않으면 미확인으로 남깁니다.
