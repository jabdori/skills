# 기존 프로젝트에 정착

[공통 지침](../_shared/personal-workflow.md)을 적용합니다. 초기화는 기존 프로젝트의 작업 기준 정비이며 새 앱 생성이나 구조 재작성 요청이 아닙니다.

## 확인과 변경

1. 프로젝트 경계, 적용되는 상위·하위 `AGENTS.md`와 기존 지침, 현재 문서·중요 결정부터 읽습니다. 관련 실행 진입점, 패키지·잠금 파일, 테스트 명령과 CI를 필요한 만큼 대조합니다. 비밀값을 읽거나 기록하지 않습니다.
2. 제품이 의도하는 동작과 실제 구현을 분리합니다. 오래된 명령이나 코드·문서의 불일치는 근거를 찾고, 해결되지 않은 제품 선택은 추측으로 덮지 않습니다. 광범위한 감사나 전체 테스트를 초기화의 필수 단계로 만들지 않습니다.
3. 기존 프로젝트 `AGENTS.md`의 잘못되거나 빠진 작업 규칙만 고칩니다. 실제 실행 위치·명령, 수정 경계, 생성 파일, 중요한 탐색 위치를 짧게 남깁니다. 현재 지원 기능·미완료 목록·실행 이력을 지침에도 복제하지 말고 현재 문서로 연결합니다. 확인하지 못한 명령을 검증 완료로 쓰지 않습니다. 다른 담당자의 규칙과 하위 지침의 범위를 보존합니다.
4. 이미 있는 README·개요를 현재 문서로 활용하고 목적·현황·다음 작업·필요한 그림을 맞춥니다. [공통 지침의 용어 지도](../_shared/personal-workflow.md#용어와-의미-지도)에 따라 혼동되는 업무 용어와 기존 참조를 연결합니다. 작은 단일 영역에 별도 용어 파일 묶음을 만들지 않습니다.
5. 변경한 지침과 실제 파일을 대조하고 수정·미확인 사항을 보고합니다. 다시 실행했을 때 새로운 사실이 없다면 기존 내용을 유지합니다. 중복 블록, 갱신 날짜만의 변경, 새 파일을 추가하지 않습니다.

## 경계와 종료

프로젝트에 맞는 작업 명령·경계·문서 진입점이 준비되면 끝냅니다. 프로젝트 초기화만으로 제품 코드, 전역 지침, 개인 스킬, CI·훅·패키지 설정을 바꾸지 않습니다. 기존 지침 파일을 일반 양식으로 통째로 교체하지 않습니다. 조사만 요청했다면 수정 없이 차이와 제안을 답합니다.

예: README의 검사 명령과 `AGENTS.md`가 다르면 실제 테스트 위치를 확인합니다. 확인한 명령만 바로잡고, 사용자 설정을 보존합니다. 이후의 일상 재개에서는 이 작업을 반복하지 않습니다.
